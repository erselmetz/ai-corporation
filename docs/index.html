AI Runtime / API

🖥️ Local AI

AI models can run locally on the Corporation's computer.

Example:

Ollama → Llama / Gemma

☁️ Cloud AI

Employees can use online AI services through supported integrations.

Examples include Gemini, OpenAI, DeepSeek, Anthropic, Kimi, and future providers.

🔑 API Access

Cloud providers may be connected through API keys, SDKs, HTTP APIs, or other supported authentication mechanisms.

Add, Remove, or Replace AI

➕ Add

New AI employees and provider integrations can be introduced without changing the Corporation's fundamental architecture.

➖ Remove

An employee or provider can eventually be removed without rebuilding the entire Corporation.

🔄 Replace

An employee can eventually be reassigned to another provider or model.

The architecture does not impose an arbitrary limit such as three, five, or ten AI systems.

Practical limits depend on hardware resources, provider limits, API limits, system performance, configuration, and available infrastructure.

Core Principles

Agent ≠ Provider ≠ Model

These are separate architectural concepts.

Local + Cloud

Local and cloud AI systems can coexist.

Extensible

New AI providers, models, and employees can be added without redesigning the Corporation.

Replaceable

AI assignments can eventually be changed without rebuilding the Corporation.

Tool Separation

AI intelligence is separate from computer-control tools.

Human Control

Sensitive operations can require human approval.
