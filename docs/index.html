ERSELMETZ AI CORPORATION

ERSELMETZ AI CORPORATION is an actual software system implementing a virtual/simulated AI organization.

The software models an organization and provides its current runtime capabilities. This site documents the implementation, its boundaries, and a roadmap that distinguishes completed foundations from planned work.

Current scope: Tasks 1–64 are implemented foundations, including the authorized FastAPI resource APIs, read-only Corporation dashboard and management pages, the internal Markdown Documentation Portal and curated Updates / Changelog page, plus in-memory Conversation and Message records with a controlled message lifecycle and an Individual Employee Chat Core service with fixed Employee/Agent targets. Local Corporation Chat now supports explicit provider replies through the Orchestrator and reviewed, confirmed pending Task creation; bounded context and permission-aware Task lifecycle snapshots are available. Explicit owner-scoped conversation notes may be retained with consent and expiry. Conversation Web/API interfaces and automatic transcript archiving remain unavailable. Browser sign-in is not configured, so protected data/actions require an authenticated session; Tasks 65–100 remain planned, not claims about current functionality.

Updates / Changelog

Find a concise record of the current documented project milestones.

Chat Context — Task 57

Added caller-supplied context bounded to 8192 UTF-8 bytes per conversation, with atomic replacement, isolation, and clearing on successful closure; no retrieval, persistence, provider calls, or chat API/UI. Trusted Core callers enforce authorization and relevance before supplying text; caller-held copies cannot be revoked. The Documentation Portal remains file-based and read-only.

Corporation Chat — Task 58

Added local Corporation Chat CLI commands with explicit coordinator Agent identity, Orchestrator-mediated replies, bounded prompts, isolated conversation history, and recorded response failures; no automatic Task creation or Web/API chat. Local chat is trusted and in-memory; explicit sends may call the configured provider, while tests use fakes. The file-based Documentation Portal is unchanged.

Corporation Task Creation via Chat — Task 59

Added immutable chat-to-Task reviews of completed user messages with explicit project and Agent routing; human CONFIRM creates a pending persisted Task without execution, and consumed reviews cannot be replayed. Reviews and local human confirmation are separate from sending chat messages. Review state is in-memory; uncertain creation failures require human inspection.

AI Activity Visualization — Task 60

Added permission-aware Task lifecycle progress to the Activity page using protected Task detail reads, with explicit pending/running/completed/failed states, separate access errors, stale-response rejection, and no fabricated provider telemetry. Select a Task ID and refresh for a current lifecycle snapshot. task:read is checked independently of activity:read. Local chat has no browser telemetry.

Memory Architecture — Task 61

Defined immutable scoped memory records with explicit owners, note/summary types, required provenance and expiry, retention opt-in, and exact owner/scope retrieval checks without automatic sharing or storage. Trusted callers bind owner identity and validate sources. Existing legacy key-value stores remain separate. Persistent conversation notes are explicitly supported by Task 62; no automatic transcript archive is added.

Persistent Conversation Memory — Task 62

Added explicitly opted-in SQLite conversation memory with immutable bounded records, owner/conversation-scoped retrieval, expiry enforcement, explicit deletion and scoped cleanup, and corrupt-data rejection; chat messages are never saved automatically. Retained notes survive chat closure until expiry/deletion. Cleanup is explicit; SQLite is plaintext. No memory HTTP/UI interface or automatic transcript archive is added.

Project Knowledge — Task 63

Added private owner-scoped durable Project Knowledge with explicit Task provenance and verified project associations; reused retention/access rules and added non-destructive Task project-ID persistence without inferring historical links. Private knowledge requires consent, expiry, and matching Project/Task references. Historical Tasks lacking project associations cannot be linked automatically. No HTTP/UI knowledge interface is added.

Corporation Knowledge — Task 64

Added explicit owner-approved Corporation Knowledge publication to bounded named-reader lists, with copied provenance and inherited expiry, deny-by-default scoped reads, owner revocation/withdrawal, and atomic durable publication; private memory is never shared automatically. Publication is a separately consented immutable copy; its owner controls revocation. Private source deletion does not withdraw publication. No knowledge HTTP/UI route is added.
