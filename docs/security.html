Boundaries and limitations

Security

This page documents controls present in the current implementation and distinguishes them from policy metadata or future plans. It is not a security certification.

Documentation-site isolation

The Node.js website inside docs/ is a presentation-only site. It reads and serves an explicit allowlist of documentation files. It does not import Python application code, connect to FastAPI, databases, Ollama, internal APIs, registries, or runtime state, execute Corporation tasks, control Agents, or modify the Corporation. It works independently when the Corporation is offline.

The Node server uses only built-in modules, supports GET/HEAD, serves an explicit file allowlist, and sends basic content-type, referrer, and content-security headers. It has no API or dynamic Corporation data endpoints.

External source and sandbox boundaries

  • GitHub discovery uses fixed public HTTPS API endpoints; source content remains untrusted data.
  • Analysis is bounded and observational. It does not execute code or install dependencies.
  • Staging validates archive paths, types, counts, sizes, and depth before writing into a controlled temporary workspace outside the project.
  • Binding and preparation recheck paths, linkage, and content hashes. A hash identifies bytes; it does not establish that they are safe or trustworthy.
  • The optional Docker backend requests restrictive isolation settings and fails closed when required controls are unavailable. There is no host-process fallback.
  • Preparation is metadata only: it does not execute staged source or transition proposals to approval/integration.

Known gaps

API authentication/authorization, encryption, networked Nodes, and a complete approval workflow are not implemented. Approval requests are in-memory and are not an execution gate. Tool permissions are not enforced by a tool execution policy. Do not infer production readiness from foundation milestones or security-related design metadata.

For additional caveats, read Documentation and Integrations.
