Optional Free pool (FreeLLMAPI)

This experimental preset is off by default. ERSELMETZ AI does not bundle, download, install or start FreeLLMAPI. Its Python app and build have no Node.js dependency. The separate router has its own installation requirements.

Install separately, then connect

  1. Open the official project and its GitHub releases. Read the selected version's requirements and choose its Windows release asset yourself. Do not copy a piped download-and-execute installer command blindly.
  2. Verify the download before running it. Compare its SHA-256 hash with trustworthy published checksums or attestations when provided; inspect its Authenticode signature and publisher where available. PowerShell can inspect files with Get-FileHash -Algorithm SHA256 and Get-AuthenticodeSignature. A signed Git commit alone does not verify an installer asset. If trustworthy asset verification is unavailable, treat the download as unverified and inspect the source rather than assuming it is safe.
  3. Start and configure the router separately. Review upstream providers, terms, data practices, keys and billing limits. In ERSELMETZ AI, open Settings → Provider connections, select Free pool, and add http://127.0.0.1:3001/v1 with the router's key. Test explicitly sends only Hi with a one-token reply limit. Inspect Not reachable, Reachable, Key rejected or No models; then enable owner-approved turns if desired.

Cloud, even on your own computer

For a generic OpenAI-compatible endpoint, choose that provider type and enter its own /v1 URL. Test initially uses the first listed model; select a different catalog model in the model list and Test again when needed. The last successfully tested generic model becomes the explicit escalation target. The Free pool preset defaults to the routing alias auto; editing its address does not verify that a particular router is installed.

Your prompt may be sent to any provider enabled in that router. Loopback is the default connection boundary, not a promise of local inference. Non-loopback endpoints require explicit confirmation and HTTPS. Keys and connection settings stay in this app process for the current run; they are not returned in settings responses.

The local model remains the default. Choose “Ask the free pool?” deliberately, including after a local failure. Review the exact redacted outbound messages and approve that one turn. Cancelling sends nothing. No automatic retry, cloud fallback or change to the Agent assignment occurs. Stop ends app work, but an already-sent request may still run or incur charges remotely.

Brain context is off per provider until enabled separately. Selected Brain excerpts must pass the existing preview and scope checks and appear in the final outbound preview. File text or prior chat/project context may be included only in that reviewed text. Obvious tokens are redacted; this is a bounded heuristic, not a guarantee that arbitrary sensitive prose can be detected. Inspect the preview. Images, screen/camera frames and recordings are unsupported. Brain embeddings remain local.

Limits and honest provenance

The official project is intended for personal experimentation. Free-tier terms and availability can change; this preset supplies no SLA or quality guarantee. Review every upstream provider's permitted use. “Free pool” does not certify zero cost: the router's enabled providers, billing and internal retries are outside this app's control.

ERSELMETZ AI caps a connection at five generation calls per app run, including Tests; prompts at 32 KB and replies at 1,024 requested tokens. This is a software allowance, not an invoice cap. Configure router/upstream account limits separately. HTTP 401, 429, 5xx, timeout and empty-model results do not trigger automatic retries.

How I answered records the router-reported provider/model from X-Routed-Via, elapsed time and this app's retry count (zero). Without the header, the served model is unknown; auto is only the requested routing alias. Router-internal retries are unknown. Tool proposals never authorize execution and are rejected until they can use the existing validated, owner-reviewed tool workflow.

SSE responses are bounded and buffered for secret/tool-proposal validation before sanitized chunks are shown. This trades immediate token display for preventing a split token or an unreviewed tool proposal from escaping early. Sync and async Python adapters share the same gates.

The supported owner journeys in this phase are Coordinator Chat and explicit native one-turn escalation. Cloud Agent tool loops, Employee/workflow cloud generation, media and embedding routes are not enabled by this preset. Paths without its exact outbound approval fail closed. Outbound redaction does not erase existing local notes or chat history; use the existing retention and deletion controls for those.

Real router checks are reported separately from fake-server contract tests. Local source verification does not publish this page, certify upstream quality or establish packaged-provider behavior.
