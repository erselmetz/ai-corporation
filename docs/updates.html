Updates / Changelog

A concise summary of documented implementation milestones. Entries describe scope, not a promise of production completeness.

Current baseline · Tasks 1–25

Corporation runtime foundations

The documented baseline includes Task and Project models, lifecycle orchestration and logs, SQLite persistence, Employee/Agent distinctions, Provider/Model management, deterministic task routing, dry-run, Corporation/Node runtime identity, command management, tool and approval foundations, and persisted routing requirements. Existing limitations remain; see Documentation.

Integration pipeline · Tasks 26–36

Controlled external-source foundations

The repository documents an in-memory proposal foundation; public GitHub discovery; bounded analysis and evidence-based evaluation; proposal generation; sandbox and execution boundaries; an optional Docker backend; inert source staging; integrity-checked sandbox binding; and immutable execution preparation. Preparation does not execute source. Testing, review, approval, and integration remain separate future work.

API foundation · Tasks 37–46

Corporation API and Web UI foundation

The Application Service and FastAPI boundary expose Corporation status, Employee/Agent resources, Provider and Model assignment operations, Task list/detail/create plus dry-run, Project list/detail/create, and bounded read-only Task activity. Activity reads require activity:read; the API returns event identifiers/names, Task IDs, and timestamps, omitting log messages that may contain internal error details. Task and Project routes use their respective permissions, return explicit schemas, and call the Application Service. Task dry-run does not execute providers or mutate Task state. No task execution or lifecycle-mutation endpoint is exposed. Authentication is injectable and rejects by default; a production identity provider is not configured.

Completed · Task 47

Read-only Corporation dashboard

The FastAPI-served dashboard at /ui loads Corporation/Node identity, Employee/Agent records, Provider/Model assignments, Task status counts, Projects, and a bounded Activity sample from the existing protected API endpoints. It sends no embedded credentials and does not weaken API permissions. Since browser sign-in/session authentication is not configured, unauthenticated, forbidden, and general request failures are shown explicitly; an authenticated session with the required per-resource read permissions remains a prerequisite for data. Provider availability and recent Task ordering are not claimed because those facts are not returned by the current API. No Task execution, management action, or provider call is added. The public Node.js documentation site remains independent from the Corporation Web UI.

Completed · Task 48

Employee Management UI

The FastAPI Corporation Web UI now includes /ui/employees for listing and viewing Employee records, creating Employees with the existing required caller-supplied ID/name/role and optional responsibilities, and removing Employees after explicit confirmation. It uses the existing endpoints and employee:read / employee:manage permissions; no Agent association changes or new API contract were added. Authentication is still fail-closed by default and browser sign-in/session integration remains a prerequisite for protected actions. The standalone public Node.js documentation site remains separate.

Completed · Task 49

Provider & Model Management UI

The FastAPI Corporation Web UI now includes /ui/providers for Provider listing/detail, creation using only the existing ID/name request, and confirmed removal. It also lists Agent Model assignments and replaces an assignment using the existing provider/model ID contract. The page uses provider:read / provider:manage and model:read / model:manage through the protected APIs. It does not expose credentials/configuration, create or modify Agents/Employees, or access Core internals. Browser authentication remains fail-closed by default and sign-in/session integration remains a prerequisite. The public Node.js documentation site remains separate.
