Domain model

The AI organization

The software system implements a virtual/simulated organization: software and organization are related, not contradictory descriptions.

ERSELMETZ AI CORPORATION is an actual software system implementing a virtual/simulated AI organization. The organization is the system's domain model and operating concept; the software implements its current capabilities.

Distinct identities and roles

ConceptMeaning in the systemCurrent implementation
CorporationIdentity of the modeled organization.Domain model and in-memory registry; local identity configured in startup code.
Node / InstallationA participating software or physical installation associated with a Corporation.Domain model; runtime validates the relationship. Networking and discovery are not implemented.
EmployeeOrganizational identity with a role and responsibilities.In-memory registry; may be associated with an Agent.
AgentTechnical execution identity with capabilities and Provider/Model references.In-memory registry; role/capability metadata supports deterministic routing.
ProviderInterface that generates a response.Ollama is the only Provider currently registered by startup.
ModelModel identifier supplied to the selected Provider.Assignment is managed in the current in-memory Agent configuration.

Organization is a software domain

“Virtual/simulated” describes the organization represented by the application. It does not mean the application is imaginary. The Corporation models organizational identities and responsibilities, then uses its runtime—registries, routing, orchestration, Providers, and persistence—to implement the currently available behavior.

Not every real-world organizational capability exists yet: for example, Employee/Agent administration is not fully persisted, approval is not an execution gate, and organization-level multi-agent collaboration is planned.

See Architecture for the current runtime structure.
