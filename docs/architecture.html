System design

Architecture

The desktop interface presents the system; the Python service owns AI and application logic.

Desktop UI

Electron hosts the Next.js interface and mediates local desktop capabilities.

Application service

Python APIs coordinate chat, tasks, projects, providers, and permissions.

Orchestration

Routing and execution use registered Agents and configured Providers.

Local data

Persistent records use the application·s configured local stores; ephemeral media remains bounded in memory.

Trusted application updates

When signed release assets are published, owners can check the fixed GitHub Releases origin and stage an installer after signature, version, migration, and SHA-256 checks. Preparation creates a SQLite backup; installation and recovery stay manual. No signed release is published yet, and the Windows installer is not Authenticode-signed.

Local performance readiness

The owner-only local readiness page reports setup timing, process memory, recorded model assignments, and queue claims from before the current app run. It never calls a model or replays work. Rendering stays measured in the browser; model workload and hardware fit remain unknown without evidence.

Encrypted local backup

In explicitly configured local mode, the owner can export safe diagnostic metadata and create encrypted backups. Preferences/configuration are selected by default; private app records require an explicit opt-in. Restore verifies the backup, stores an encrypted local pre-restore copy, and requires an app restart. The passphrase cannot be recovered. Provider-side data, model files, and credentials stored outside the app database are excluded.

Boundary: Public documentation is a separate, read-only site. It does not access or control the running application.
